# D2 動畫系統重構任務

## 任務名稱：將現有正確動畫逆向整理成「Standard Animation Template + Shared Animation Builder」

你現在的任務不是單純新增動畫。

你的首要任務是：

> **把目前專案中已經能正確顯示、方向正確、Frame 播放正確、Offset 正確、組合正確的現有動畫，全部逆向分析，找出它們共同遵循的規則，然後重構成一套可供所有未來 D2 動畫共用的標準動畫模板與共用 Builder。**

完成後，未來加入新的角色、怪物、技能、投射物、死亡動畫、攻擊動畫、施法動畫等，都必須優先走這套共用 Pipeline，而不是為每個動畫重新寫一套特殊處理。

3. 不要只依照檔名判斷。
4. 必須根據實際程式碼、輸出資料、Manifest、Atlas、執行邏輯與畫面結果來判斷。

實際專案中有哪些，就使用哪些。

不要自行假設不存在的動畫。

# 4. 尋找成功動畫之間的共同規則

這一步非常重要。

將目前所有成功動畫做交叉比對。

找出：

## 4.1 資源解析共同規則

確認：

```text
MPQ
→ Resource
→ DCC
→ COF
→ Palette
→ Animation
```

之間到底如何解析。

不要根據檔名猜測。

如果專案已經有正確的 Resolver，將其抽出成共用模組。

---

## 4.2 Direction 共同規則

找出現有成功動畫如何處理：

```text
World Direction
        ↓
Logical Direction
        ↓
DCC Direction
```

不要直接：

```text
sprite rotate 45°
```

也不要讓不同動畫各自使用不同方向算法。

建立統一方向介面，例如：

```text
World Direction
Logical Direction
Asset Direction
```

實際命名依現有程式碼決定。

必須支援不同動畫可能存在：

```text
4 directions
8 directions
16 directions
32 directions
```

甚至其他實際 D2 資源形式。

不要硬編碼所有動畫都一定 16 方向。

---

# 5. 逆向整理 Frame 結構

分析成功動畫目前如何取得：

```text
Frame 0
Frame 1
Frame 2
Frame 3
...
```

確認：

* Frame 是否依方向分組
* Frame 是否有獨立 Offset
* Frame 是否有 Width / Height
* Frame 是否存在 origin
* Frame 是否存在 pivot
* Frame 是否存在 layer
* Frame 是否需要 compositing
* Frame 是否直接來自 DCC
* Frame 是否由多個 DCC layer 組成

建立統一 Frame 結構。

例如概念上：

```json
{
  "frame": 0,
  "width": 64,
  "height": 80,
  "offsetX": -32,
  "offsetY": -70,
  "anchorX": 32,
  "anchorY": 70,
  "duration": 40,
  "atlas": {
    "x": 128,
    "y": 64,
    "w": 64,
    "h": 80
  }
}
```

實際欄位依現有專案需求決定。

不要為了範例而硬套不必要欄位。

---

# 6. 逆向整理 Anchor / Offset

這是非常重要的一項。

分析目前成功動畫為什麼沒有：

```text
角色上下抖動
角色左右漂移
角色腳底漂移
角色施法時位置跳動
投射物方向發生位移
```

找出它實際採用的：

```text
Entity World Position
        +
Sprite Anchor
        +
Frame Offset
        ↓
Screen Position
```

建立統一 Anchor 系統。

角色、怪物、技能、投射物都必須使用相同概念。

例如：

```text
World Position = 實體在遊戲世界的邏輯座標

Anchor = 該動畫應該固定在世界座標上的參考點

Frame Offset = 每張圖片相對 Anchor 的偏移

Screen Position = Isometric Projection(World Position)
                 + Animation Offset
```

禁止使用「每個動畫手工調一組畫面座標」的方式解決問題。

---

# 7. 逆向整理 COF / Layer Composite

確認目前成功動畫是不是單一 DCC。

如果不是，必須找出：

```text
COF
 ↓
Layer 0
Layer 1
Layer 2
Layer 3
...
 ↓
Composite Frame
```

例如：

```text
Body
Arm
Weapon
Shield
Effect
Overlay
```

建立通用 Composite Animation 機制。

概念：

```text
CompositeAnimation
├── Layer 0
├── Layer 1
├── Layer 2
├── Layer 3
└── Layer N
```

每一層都必須能夠有：

```text
Token
DCC
COF Layer
Palette
Direction
Frame
Offset
Blend
Draw Order
```

不要把目前成功動畫中寫死的 Layer 組合方式保留在單一技能裡。

---

# 8. 逆向整理 Palette

確認成功動畫的顏色到底怎麼取得。

分析：

```text
DCC
+
Palette
=
RGBA Frame
```

確認目前程式是否存在：

```text
固定 Palette
Palette Variant
Character Palette
Monster Palette
Skill Palette
Color Transform
```

把通用部分抽出。

如果相同 DCC 僅因 Palette 不同而產生不同顏色，不應該複製大量重複資產。

優先設計成：

```text
Shared Base Asset
        +
Palette Variant
        ↓
Visual Variant
```

# 9. 逆向整理 Animation Timing

確認成功動畫的真正播放速度。

不要直接假設：

```text
FPS = 25
```

必須找出實際來源。

可能來源包含：

```text
AnimData
Animation metadata
COF
TXT
Skill data
自訂 Timing
```

分析成功動畫之後，建立統一 Timing 結構。

例如：

```json
{
  "fps": 25,
  "frameDuration": 40,
  "loop": true
}
```

或：

```json
{
  "frameDurations": [
    40,
    40,
    60,
    80,
    40
  ]
}
```

視成功動畫的真實需求設計。

# 10. 逆向整理 Animation Event

特別分析技能動畫。

例如 Fireball：

```text
Cast Start
   ↓
Cast Frame 0
   ↓
Cast Frame 1
   ↓
Cast Frame 2
   ↓
Cast Frame 3
   ↓
Projectile Spawn
   ↓
Cast Frame 4
   ↓
Cast End
```

不能簡單寫成：

```text
cast()
→ spawn projectile immediately
```

必須建立 Animation Event。

例如：

```json
{
  "frame": 3,
  "event": "projectile_spawn"
}
```

未來可以支援：

```text
projectile_spawn
hit
sound
effect
camera_shake
attack
damage
animation_end
state_change
```

Event 系統必須與動畫播放核心分離。

# 13. Builder 必須資料驅動

新增動畫不應該需要：

```text

新增一個新的 JS animation class
新增一套特殊 Direction 算法
新增一套特殊 Offset
```

```json

    "mode": "...",
    "dcc": "...",
    "cof": "...",
    "palette": "..."
  }
}
```

然後：

```text
builder.build("new_animation")
```

即可產生標準動畫資料。

# 31. 最終目標

我要的是：

```text
不是：

「我們已經做出很多動畫」

而是：

「我們已經建立一套可以持續製作 D2 動畫的系統」
```

真正的最終架構：

```text
               D2 Raw Assets
                     │
                     ▼
             Resource Resolver
                     │
                     ▼
         ┌────────────────────────┐
         │ Shared Animation Builder│
         ├────────────────────────┤
         │ DCC                    │
         │ COF                    │
         │ Palette                │
         │ Direction              │
         │ Frame                  │
         │ Timing                 │
         │ Anchor                 │
         │ Offset                 │
         │ Layer                  │
         │ Event                  │
         └───────────┬────────────┘
                     │
                     ▼
          Standard Animation Data
                     │
                     ▼
              Atlas + Manifest
                     │
                     ▼
               Web Runtime
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       Character   Monster     Skill
          │          │          │
          └──────────┼──────────┘
                     ▼
               Same Pipeline
```

## 最終規則

**一次把「成功動畫」的正確邏輯找清楚。**

**把正確邏輯放進 Shared Builder。**

**舊動畫全部回歸驗證。**

**之後所有新動畫一律走 Shared Builder。**

**不要再讓 Agent 為每一個新動畫重新猜一次 D2 的動畫組合方式。**

這份提示詞比較適合你現在的狀況，因為它不是單純要求 Agent「抽象化程式碼」，而是強制它先把**現有成功案例當作 Ground Truth**，再建立共用系統。這樣可以避免把目前那些「看似能動、實際上方向或 Offset 不完全正確」的邏輯直接抽成錯誤模板。
