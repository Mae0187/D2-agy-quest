# 一、最重要：D2 動畫的單位是「Animation Clip」

你最後不要寫成：

```javascript
play("image_001.png");
play("image_002.png");
play("image_003.png");
```

而應該建立：

```javascript
const animation = {
    actor: "barbarian",

    mode: "RN",

    direction: 5,

    frames: [
        ...
    ],

    fps: 25
};
```

概念上：

```text
Barbarian
 │
 ├─ mode = NU   // idle
 ├─ mode = RN   // run
 ├─ mode = A1   // attack 1
 ├─ mode = A2   // attack 2
 ├─ mode = SC   // spell/cast
 ├─ mode = DT   // death
 └─ ...
```

這些 Mode / COF 組合才是「遊戲動畫」。

COF 本身就是拿來組合動畫 layer、direction、frame 等資訊的；OpenDiablo2 也為 COF 建立了獨立的方向映射與 animation metadata。([GitHub][3])

# 三、為什麼不能直接把你這張圖全部切成固定大小

因為 **D2 的 DCC frame 不是一般現代 sprite sheet 的固定格子動畫。**

這一點非常重要。

DCC 每個 direction 裡面有自己的 frames，而且 frame 可以有自己的 bounding box / offset。OpenDiablo2 的 DCC animation decoder 會把每個 direction 的 frame 尺寸和 `Box.Left / Box.Top` 當成 frame offset 保存。([GitHub][2])

所以真實情況可能是：

```text
Frame 0
┌────────┐
│        │
│   ●    │
│        │
└────────┘

Frame 1
┌──────────┐
│          │
│    ●     │
│          │
└──────────┘

Frame 2
┌───────┐
│       │
│ ●     │
│       │
└───────┘
```

三張圖的尺寸根本不需要相同。

可是角色在遊戲中仍然要：

```text
腳底固定
      ↓
   ● 人物
```

而不是：

```text
Frame 1
     ●

Frame 2
        ●

Frame 3
  ●
```

這就是 **anchor / offset** 的用途。

# 五、方向不是 8 張圖那麼簡單

D2 的方向系統也不能直接寫：

```javascript
direction = Math.floor(angle / 45);
```

正確思路是：

```text
移動向量
   ↓
World Direction
   ↓
Canonical direction
   ↓
DCC direction
```

OpenDiablo2 的 DCC 實作直接限制 canonical direction 為 64 個，再依照動畫實際 direction 數量映射到 DCC direction。([GitHub][2])

例如：

```text
64-direction space
        ↓
      DCC
        ↓
  8 / 16 / 32 directions
```

所以你的 runtime：

```javascript
direction64 = getDirection(dx, dy);
dccDirection = mapDirection(
    direction64,
    animation.numberOfDirections
);
```

這樣才能正確。

# 十、然後 PixiJS 播放器就是非常簡單

概念：

```javascript
class D2Animation {

    constructor(frames, fps = 25) {
        this.frames = frames;
        this.fps = fps;
        this.time = 0;
    }

    update(dt) {
        this.time += dt;

        const frameDuration = 1 / this.fps;

        return Math.floor(
            this.time / frameDuration
        ) % this.frames.length;
    }
}
```

渲染：

```javascript
const frameIndex = animation.update(deltaTime);

sprite.texture =
    animation.frames[frameIndex];
```

但這只是 **D2-like runtime**。

# 十一、要更接近 D2，時間不要直接寫死

前面提過，D2 的核心時間尺度是 25 ticks/sec，而動畫實際速度還受到資料中的動畫速度資訊影響。

OpenDiablo2 的 helper 會依 COF speed 計算動畫 FPS：

```text
FPS = 25 × Speed / 256
```

所以：

```text
Speed 256
→ 25 FPS
```

而：

```text
Speed 128
→ 12.5 FPS
```

([GitHub][2])

因此你的 AnimationClip 最終應該：

```javascript
{
    mode: "A1",
    directions: 16,
    frames: [...],
    speed: 256
}
```

而不是：

```javascript
{
    fps: 60
}
```

瀏覽器可以 60 FPS / 144 FPS rendering，但 **遊戲動畫時間尺度不要因此變成 60 FPS 動畫**。
