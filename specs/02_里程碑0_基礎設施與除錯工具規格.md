## 1. 時鐘與渲染解耦架構 (Clock & Rendering Decoupling)

### 1.1 25Hz 固定步長邏輯累加器
* 邏輯步進嚴格維持暴雪原廠 25Hz（1 Tick = 40ms），所有彈道飛行、冷卻時間、召喚物生命週期皆以 Tick 為整數計數。
* 引入 `MAX_CATCHUP_TICKS = 5` 防止使用者切換分頁或瀏覽器背景掛起後恢復時引發的「追趕死亡螺旋」。

```ts
const TICK_MS = 40;
const MAX_CATCHUP_TICKS = 5;
let acc = 0, last = performance.now();

function mainLoop(now: number) {
  acc += Math.min(now - last, TICK_MS * MAX_CATCHUP_TICKS);
  last = now;
  while (acc >= TICK_MS) {
    world.snapshotPrev();         // 實體記錄 prevX = x, prevY = y
    world.stepTick();             // 邏輯推進 1 Tick
    acc -= TICK_MS;
  }
  render(world, acc / TICK_MS);   // 畫面插值比例 alpha ∈ [0, 1)
  requestAnimationFrame(mainLoop);
}
```

### 1.2 整數動畫幀累加器 (Integer Frame Accumulator)
嚴禁按毫秒生硬切幀，必須在邏輯 Tick 內以整數累加器步進（`speed` 源自 `AnimData.D2` 的 `AnimationSpeed` 欄位，256 代表每 Tick 前進 1 幀）：
```ts
anim.acc += anim.speed;
while (anim.acc >= 256) {
  anim.acc -= 256;
  anim.frame = (anim.frame + 1) % anim.frameCount;
}
```
此機制保證德魯伊（6幀）、死靈（8/12幀）、野蠻人（19幀）各按原廠速度流暢運轉，餘數永不丟失，週期精確無誤。

### 1.3 畫面渲染位置平滑插值 (Position Interpolation)
* 渲染時依據當前累積餘額 `alpha` 對實體位置進行線性插值：
  $$\text{renderX} = \text{round}(\text{prevX} \cdot (1 - \alpha) + \text{currX} \cdot \alpha)$$
  $$\text{renderY} = \text{round}(\text{prevY} \cdot (1 - \alpha) + \text{currY} \cdot \alpha)$$
* **強制取整**：插值結果最後必須以 `Math.round` 轉為整數像素再繪製，防止次像素（Sub-pixel）渲染導致暗黑 2 像素點陣圖邊緣發糊或抖動閃爍。
* **瞬移保護**：若實體觸發傳送（Teleport）或換場景，設置 `teleported = true`，當幀 `prevX = currX`，杜絕橫跨全螢幕的拖影。

### 1.4 四級常駐節能降頻機制 (Power-Saving Strategy)
作為常駐桌面或懸浮看板，必須嚴格控制 CPU 與筆記型電腦電量：

| 狀態模式 | 觸發條件 | 渲染幀率 (Render FPS) | 邏輯幀率 (Logic Hz) | 節能策略 |
| :--- | :--- | :--- | :--- | :--- |
| **ACTIVE** | 看板處於前景且獲得焦點 | 60 FPS (依螢幕垂直同步) | 25 Hz | 全特效開啟，粒子全開 |
| **AMBIENT** | 看板可見但失去焦點（主要常駐狀態） | 24~30 FPS (時間戳跳幀) | 25 Hz | 粒子上限減半，關閉 LOD 2 高階後製光效 |
| **IDLE_DEEP** | AI Agent 處於 IDLE 超過 60 秒 | 8~12 FPS | 10~25 Hz | 僅保留營火呼吸與角色站立擦拭動作 |
| **HIDDEN** | 視窗最小化或 `document.hidden` | **0 FPS（停止 rAF）** | **暫停模擬** | 靜音、暫停遊戲主循環，僅保留事件監聽器 |

## 2. 投射物方向校準系統 (Direction Calibration System)

### 2.1 地面平面螢幕角 $\phi$ 之標準約定
* **定義**：在 2:1 等距幾何下，定義地面平面螢幕角 $\phi$：
  $$\phi = \text{atan2}(dy \cdot 2, dx)$$
  其中 $dx, dy$ 為螢幕像素位移量。
* **方向約定**：$\phi = 0^\circ$ 為螢幕正右方（正東），因螢幕 Y 軸向下，故 $\phi$ 數值遞增代表**視覺上的順時針旋轉**。校準資料一律統一儲存 $\phi$。

### 2.2 四組校準測試向量 (Test Vectors)
1. **A 組（數學可逆往返，72 點）**：$\phi$ 從 $0^\circ$ 到 $355^\circ$ 每 $5^\circ$，驗證投影與逆變換精確度 $|\phi' - \phi| < 10^{-9}$。
2. **B 組（離散邊界探測）**：各離散方向切換邊界（半步角）的 $\pm 0.5^\circ$，檢驗四捨五入與 $360^\circ$ 循環繞回（Wrap-around）。
3. **C 組（數學對照組）**：計算未乘 2 的錯誤角度 $\text{atan2}(dy, dx)$ 與正確 $\phi$ 之殘差，繪製誤差曲線，驗證理論最大偏差剛好為 **19.5°**（嚴格發生於 $\tan\theta = \sqrt{2}$ 處）。
4. **D 組（視覺疊加）**：每個投射物在 72 個角度各射出一發，畫面上繪製理論方向箭頭並與實際貼圖重合比對。

### 2.3 自動 PCA 量測演算法（細長型投射物）
對箭矢、長矛、骨矛、冰刺等細長型 missile，透過影像主軸分析自動判定方向：
1. 提取各方向代表影格之 Alpha 通道。
2. 進行 Alpha 加權主成分分析（PCA），求得主軸角度 $\alpha_i$ 與離心率 $\lambda_1 / \lambda_2$。
3. 轉換為主軸地面角：$\phi_i = \text{atan2}(ay \cdot 2, ax)$。
4. 依沿主軸方向的像素寬度偏態判定箭頭與箭尾（尖端窄、尾羽寬）。
5. 擬合方向公式：$\phi_i = \text{dir0} \pm i \cdot (360^\circ / N)$，以最小殘差判定順時針/逆時針與基礎偏角 $\text{dir0}$。
6. 若離心率 $< 1.3$（如火球、電球），自動判定為無方向性 `rotationMode: 'none'`。

### 2.4 校準資料結構 (TypeScript)
```ts
interface DirectionCalibration {
  missileId: string;
  celFile: string;
  dirCount: 1 | 8 | 16 | 32;
  dir0WorldAngle: number;        // 單位：度 [0, 360)
  clockwise: boolean;
  rotationMode: 'discrete' | 'none' | 'free';
  measure: {
    method: 'auto' | 'manual';
    residualMaxDeg: number;
    eccentricity: number;
    confidence: number;          // 0.0 ~ 1.0
  };
  status: 'auto-pass' | 'needs-review' | 'manual-confirmed';
}

function getDirIndex(phiDeg: number, c: DirectionCalibration): number {
  const step = 360 / c.dirCount;
  const rel = c.clockwise ? phiDeg - c.dir0WorldAngle : c.dir0WorldAngle - phiDeg;
  return ((Math.round(rel / step) % c.dirCount) + c.dirCount) % c.dirCount;
}
```
**驗收通過門檻**：全角度下，貼圖實際朝向與理論 $\phi$ 之誤差 $\le 0.5 \times \text{step}$（8方向 $\le 22.5^\circ$，16方向 $\le 11.25^\circ$）。

## 3. 圖層與動畫檢查器 (Layer & Animation Inspector)

### 3.1 COF 結構一致性檢查 (A1 ~ A5)
* **A1 各圖層幀數一致性**：對同一動作，列出啟用的所有部件（身體、頭、武器、盾牌），圖層總幀數必須 100% 等於 COF 的 `FramesPerDirection`。任何不等直接判定失敗。
* **A2 方向數一致性**：圖層 DCC 方向數、COF 定義方向數與 AnimData 三方比對必須吻合。
* **A3 部件圖層缺失**：檢查該裝甲類別下的必備圖層是否存在（杜絕「無頭死靈」或「缺盾亞馬遜」）。
* **A4 優先序表完整性**：COF 前後遮罩順序表每一幀必須完整定義，無空洞或重複。
* **A5 武器動作匹配**：檢查動作代號與當前武器（1HS, 2HS, STF, BOW, JAV）是否在資產庫中存在對應圖層。

### 3.2 局部偏移連續性與抖動檢驗 (B1 ~ B5)
* **B1 合成包圍盒抖動**：計算合成影格的接地點與中心，相鄰幀位移之 Z-score $> 3$ 即標記警告。
* **B2 單圖層錨點跳變**：各圖層局部偏移序列之二階差分超出閾值即標記警告。
* **B3 循環接縫跳動**：最後一幀回到第 0 幀的接縫位移比值 $> 2$ 即標記警告（常見走路卡頓根因）。
* **B4 待命漂移檢驗**：待命循環內腳底接地點全週期總漂移必須 $< 0.5\text{px}$（徹底根治德魯伊站立發抖）。
* **B5 基準比對**：以刺客為黃金基準，輸出各職業偏離度評分。

### 3.3 步頻防滑步檢驗 (Foot Sliding Check)
* **週期時長**：$\text{cycleTicks} = \text{frameCount} \times 256 / \text{animSpeed}$。
* **每週期地面位移**：$\text{strideWorld} = \text{moveSpeed} \times \text{cycleTicks}$。
* **滑步率量測**：追蹤接觸地面階段支撐腳相對於地面的相對滑動速率，若滑動率異常，自動給出理論最佳匹配移動速度建議。

## 4. 混色模式列舉與黑邊防御體系

混色模式（BlendMode）與調色盤染色（PaletteShift）為兩個獨立維度，封裝為標準列舉：

```ts
enum BlendMode {
  Normal,      // 普通 Alpha，調色盤 Index 0 為純透明
  Alpha25,     // 25% 半透明
  Alpha50,     // 50% 半透明
  Alpha75,     // 75% 半透明
  Additive,    // 加法混色 (DirectDraw Trans: 1) -> Canvas 'lighter'
  Screen,      // 濾色 -> Canvas 'screen'
  Luminance,   // 亮度轉 Alpha（純黑自動透明）
  Multiply,    // 暗化正片疊底（地表陰影、焦痕） -> Canvas 'multiply'
  Shadow       // 角色扁平傾斜暗黑陰影專用
}

interface DrawStyle {
  blend: BlendMode;
  alpha?: number;
  paletteShift?: 'freeze' | 'poison' | 'lightning' | 'fire' | 'uniqueTint';
  tint?: [number, number, number];
}
```

### 4.1 黑邊與暗灰光斑三層防御
1. **模式嚴格對應**：火焰、電弧、神聖金槌等發光特效必須指定為 `BlendMode.Additive`，嚴禁使用 `Normal`。
2. **調色盤邊界清潔**：導出 PNG 精靈圖時，Index 0 必須嚴格映射為 `RGBA(0, 0, 0, 0)`，且邊緣過渡像素不得混入低亮度雜散灰度。
3. **Premultiplied Alpha 隔離**：確保瀏覽器解碼與 Canvas 繪製管線中未重複執行預乘 Alpha 計算。
